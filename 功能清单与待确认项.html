1. 项目概述

本系统是一套面向客户生产管理层的车间统一监控与岗位交接中心演示原型，定位为「一块专属大屏 = 一个子系统、多屏构成监控室」。当前主线已接入客户真实数据，覆盖 Output（产出）/ WIP（在制品）/ 次品管理（质量） 三大车间子系统，并配套预警、邮件、配置、周维度对账、生产日志与平台底座能力。

技术栈 纯静态站点：HTML + CSS + 原生 JS，零依赖、零构建、离线可用
交付形态 双击 index.html 即可打开，或 python -m http.server
真实数据 已接入客户 IT 导出报表（产出/WIP/次品），其余周回落演示剖面
本清单依据项目源码与 README.md 逐页梳理，覆盖 14 个页面 + 公共引擎，按信息架构三层（监控室 / 专属大屏 / 平台底座 + 标配 + 分析归档）组织。
★ 核心优势

2. 项目核心优势（拿项目关键点）

以下为面向客户争取项目时的核心卖点，区别于「普通 BI 报表」与「需逐一对接第三方系统」的方案。

  1. 原生打通我方已落地多套系统：WIP / 产出 / 不良、设备报修、模具管理、COMP 塑封料出库解冻，无需对接第三方，实施风险低、交付快。 对应能力：三大车间大屏 + 设备/模具/物料台账联动（见第 5.2 节范围确认）
  2. 不止看结果数据，更能自动联动根因：异常时自动联动机台工单、模具履历、塑封料解冻时效，快速定位根因——设备故障 / 模具问题 / 塑封料时效异常，不用多系统人工查询。 对应能力：跨业务根因分析、工单联动（analytics / 报警联动）
  3. 匹配生产经理核心诉求：Lot 全链路追溯定位卡料批次；交付风险预判，综合设备停机、模具保养、物料超时等因素预估产能缺口；统一时效预警（工序 OTD、COMP 解冻、模具保养）；生产报警可联动设备 / 模具工单闭环。 对应能力：WIP 工序×料号追溯、统一时效阈值预警、报警→工单闭环
  4. 普通 BI 做不到的跨业务台账：普通 BI 只能做静态报表，没有这套模具、设备、物料业务台账，无法实现跨业务根因分析与工单联动。 对应能力：我方既有业务台账 + 统一监控中心，是可复用资产而非从零开发
  5. 分阶段落地，风险可控：V1 聚焦车间主线（产出 / WIP / 次品 + 时效预警），C-SAM、订单、来料等可二期扩展。 对应能力：按屏排期、暂缓看板占位、小步快跑（见 README §三）
一句话定位：不是再建一套 BI，而是把我方已落地、已验证的车间业务系统（WIP/产出/不良/设备/模具/物料）原生打通，做成统一监控 + 根因联动 + 交接闭环的中心。

5. 需要跟客户确认的功能点

以下为正式立项 / 实施前需客户拍板或澄清的事项。第 5.1 项（数据闭环）是本次调研的核心决策点，建议优先确认；其余为范围 / 边界类待澄清项。已确认落地口径见第 6 节，不在本清单重复列为待确认。

5.1 是否与对接系统形成「数据闭环」核心决策点

问题背景：本系统作为统一监控与岗位交接中心，会在发现问题时向相关责任处室发出告警 / 警告。关键问题：告警发出之后，对方（责任处室）的回复与处置反馈是否要回到本系统？

方案 A · 双向闭环（本系统内回复）

  • 对方在本系统内直接回复、认领、填写处置结果；
  • 本系统回写状态（待处置 → 处理中 → 已闭环）并留痕责任人与时间；
  • 告警流水、交接单、KPI 直接与处置状态联动；
  • 客户可在统一中心看到「谁、何时、怎么处置的」。
需要对接系统开放「回复 / 认领 / 处置反馈」写接口，对接系统需配合改造。

方案 B · 单向告警 + 原有系统处置（半闭环）

  • 本系统只发告警 / 通知，不接收回复；
  • 对方在其原有系统里查找、处置，并做交接回复；
  • 本系统不接收回复，仅做告警记录与交接单/日报追踪；
  • 「是否闭环」由本系统凭交接单或派单状态自行标记。
对接系统无需开放写接口，实施成本低、周期短，但闭环完整性依赖人工核对。
需要客户拍板 / 澄清的问题：
  • 告警发出后，对方是否需要在本系统内直接回复、认领并反馈处置结果（方案 A），还是可以接受在原有系统内查找、处置并做交接回复（方案 B）？
  • 若选方案 A，需要对接系统开放哪些写接口？（回复内容、处置状态、责任人、处置时间、备注等）
  • 「已闭环」的判定标准：以对方在本系统的回复为准，还是本系统自行标记即可？
  • 是否要求状态双向同步？例如原系统处置完成后，本系统能否自动感知并回写状态？
  • 若选方案 B，客户是否能接受「告警仅通知、闭环在原有系统完成、本系统凭交接单 / 日报做追踪」这一弱闭环模式？
影响评估：方案 A 的体验与数据完整性更好，但对接系统改造工作量、接口安全评估、实施周期显著更高；方案 B 落地最快、对既有系统零侵入。建议结合对接系统开放程度与排期决定，必要时「先 B 后 A」渐进式路线。注意：第 2 节核心优势中的「工单闭环」指我方系统内部的报警→设备/模具工单联动，与本条「跨系统回复闭环」是两个层面，可分别落地。
